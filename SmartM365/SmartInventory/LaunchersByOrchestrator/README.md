# LaunchersByOrchestrator

These launchers do not run a collector themselves. Each one submits a request to the resident
orchestrators through `Orchestrator/SmartM365-Inventory-Pipeline.ps1 -Job <name> -Collect`:

- the job runs on its elected server, with the shared occurrence claims, concurrency locks,
  capability checks and retry policy of the orchestrator, so it can never overlap a scheduled run;
- dependencies are not rerun. For a dependency outside the request, the orchestrator applies the
  job's scheduled rule (for example `FreshSuccess` for `WorkplaceEvidence-Prepare`); the job waits,
  then fails with `BlockedDependencyTimeout` instead of consuming stale data;
- the launcher waits for the result. Exit code `0` = success, `3` = completed with warnings,
  `1` = failure, rejection or timeout.

| Launcher | Use |
| --- | --- |
| `Request-<JobName>.cmd` | One launcher per non-manual job of the jobs manifest template. |
| `Request-SmartM365-OrchestratorJob.cmd JobA[,JobB]` | Any job(s) by name. |

Optional arguments: `-IncludeDependencies` (also run the enabled dependencies in the same request),
`-NoWait` (return once the request is published).

Only one pipeline request can be active at a time. A job disabled or manual in the shared
manifest is refused at submission.

The files are generated by `Orchestrator/New-SmartM365-OrchestratorJobLaunchers.ps1` from
`Orchestrator/Orchestrator-Jobs.json.template`; do not edit them. The offline test
`Tests/Test-SmartM365OrchestratorPipeline.ps1` fails when they are out of date.

For an immediate run on the current server, without the orchestrator, use `../Launchers/`.
