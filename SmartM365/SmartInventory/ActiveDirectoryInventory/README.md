# Active Directory Inventory

Active Directory inventory and reporting scripts.

## Scripts

- `SmartM365-ActiveDirectory-Inventory.ps1`: full AD inventory across domains, combined CSV generation, duplicate checks, weekly inventory history, and daily AD computer/user reports.
- `SmartM365-ActiveDirectory-HealthCheck.ps1`: AD forest health check across domains and domain controllers, with CSV export, mail report, LOG-ALL log/transcript finalization, and SharePoint upload when enabled.
- `SmartM365-ActiveDirectory-Adaxes-Inventory.ps1`: users' attributes read through Adaxes, including Adaxes virtual attributes (`adm-*`), published as `AD_Adaxes_Users.csv`. See [Adaxes attributes](#adaxes-attributes).
- Use `SmartM365-ActiveDirectory-Inventory.ps1 -ReportOnly` to regenerate daily reports from existing consolidated inventory CSV files without a live AD scan.

Versions 1.44 (inventory), 1.0.22 (health check), 1.3 (computer enrichment)
and 1.6 (user enrichment) publish current CSVs, append histories and manifests
through same-folder temporary files. A failed domain collection now blocks the
combined inventory instead of promoting a partial forest result. These changes do
not alter the existing CSV columns, identity keys, health thresholds or enrichment
rules. Detailed synthetic audit evidence is retained outside the public repository.

## Enriched CSV schema

The canonical Active Directory inventory files contain the enriched schema:

- `AD_Users_AllDomains.csv`
- `AD_Computers_AllDomains.csv`

The direct AD exports use an explicit raw suffix:

- `AD_Users_AllDomains_Brut.csv`
- `AD_Computers_AllDomains_Brut.csv`

Active Directory attribute names remain unchanged. Calculated columns use the same canonical names when they are present in both raw and enriched files.

## Duplicate Identity Notification

During a full inventory, the daily summary and identity diagnostics are sent in one email when duplicate UPNs, duplicate SMTP proxy addresses, duplicate remote routing addresses, or remote mailbox routing inconsistencies are found. `-DuplicateAnalysisOnly` sends only the identity diagnostic email; `-ReportOnly` sends only the daily summary email.

Remote mailbox detection uses the exact Active Directory attributes `msExchRemoteRecipientType` and `msExchRecipientTypeDetails`. Validation compares `targetAddress` and `proxyAddresses` with `RemoteRoutingDomain` from the selected local profile, for example `Config/Tenants/prod.local.json`. The profile name only selects the configuration file; it is never used to construct the routing domain. If `RemoteRoutingDomain` is empty, the script derives `<tenant>.mail.onmicrosoft.com` from `OrgDomain` in that profile.

The mail includes per-domain summary tables, dated comparisons with the previous available scan and exact J-7/J-30 scans, configurable inline previews (default top 10), and one attached `AD_Users_IdentityAndMailRoutingIssues.xlsx` workbook with a worksheet for each diagnostic dataset. The workbook is also uploaded to SharePoint when enabled; its link appears with the other SharePoint links at the bottom, immediately above Paths. `DuplicateNotificationPreviewLimit` (1-50) controls preview length, and `ShowMailLinks` controls whether SharePoint and path links appear in the mail. Both settings belong in the private script-local JSON configuration; the committed template provides safe defaults.

Summary object totals count parsed CSV records, including records with quoted line breaks. Historical computer, group, and contact totals created by the former physical-line counter are shown as `n/a` in comparisons until a comparable logical-count snapshot exists. J-7 and J-30 require a scan on the exact target date.

The canonical CSV files remain published separately to DATA-ALL, DATA-LAST, SharePoint, and weekly history when applicable:

- `AD_Users_DuplicateUPN.csv`
- `AD_Users_DuplicateSMTP.csv`
- `AD_Users_DuplicateRemoteRoutingAddress.csv`
- `AD_Users_RemoteRoutingIssues.csv`

These four diagnostic files are always generated with their canonical header, including when the result contains zero rows. When duplicate analysis is enabled, all four files are required before the weekly snapshot can be marked complete.

Remote routing issues cover:

- missing or invalid `targetAddress`;
- a `targetAddress` outside the configured tenant routing domain;
- a `targetAddress` missing from `proxyAddresses`;
- no proxy address in the configured `<tenant>.mail.onmicrosoft.com` domain.

## Daily Reports

Daily computer and user stats are now generated by the inventory script from the consolidated inventory CSV files:

- `AD_Computers_DailyStats.csv`
- `AD_Users_DailyStats.csv`

Useful settings in `SmartM365-ActiveDirectory-Inventory.local.json`:

- `AdEnrichmentWindowsUpdateAnchorPolicyId`, `AdEnrichmentWindowsUpdate24H2PolicyId`, and `AdEnrichmentWindowsUpdate25H2PolicyId`: environment-specific policy IDs. Set them in the ignored local JSON; the committed template and script defaults are empty.
- `NonBlockingDomainErrors`: domain names whose transient AD connectivity errors, including retries and final unavailability, are logged as informational events. The script still attempts these domains. Starting with inventory 1.58, an unrestricted inventory can qualify for CMDB consumption with explicit partial domain coverage: at least one domain must complete, every missing domain must have an actually tolerated connectivity failure, and all required CSVs must be produced in the same run without collection errors. The receipt retains `IsPartialInventory=true`, declares `DomainCoverage`, and never claims a complete forest. CMDB displays the missing domains in `SourceHealth`. Failed-domain fragments and old domain exports are not included. The default is an empty list. When configured, domain collection runs serially so failures are tracked accurately. Other domain failures, restricted/report-only runs and missing required exports remain blocking.
- `EnableDailyReport`: defaults to `true`.
- `DailyReportAllowedOS`: defaults to Windows 7/8/10/11 patterns.
- `DailyReportInactiveDays`: defaults to `90`.
- `EnableDailyReportLock`: defaults to `true` to avoid appending duplicate daily rows.
- `DailyReportLockRoot` and `DailyReportLockName`: configure the success lock location/name.


## Daily Summary Email

Five cards at the top of the email Summary show current-snapshot users, computers, groups, affected duplicate UPN accounts, and affected duplicate SMTP entries. Each card also shows its change from the previous dated scan when the recorded domain set matches. A coverage banner shows the current and previous domain counts and whether the sets match. The cards do not imply that a partial inventory covers the full forest.

The inventory script also writes `AD_Inventory_DailySummary.csv` and can send one daily synthesis email to the configured `To` recipients. The email uses the shared SmartM365 template and compares the current scan with the latest summary snapshot from a previous day. Same-day snapshots are ignored for the diff because the script can run several times per day. The summary history records `CollectedDomains` as a normalized, semicolon-separated domain list. Existing history rows receive an empty value during an atomic schema update; their inventory and duplicate deltas remain `n/a` until a new comparable scan exists. Previous values remain visible in the diff table. Computers, groups, and contacts also retain their logical-count compatibility gate. Duplicate increases are highlighted as adverse and decreases as favorable; other inventory-count changes are neutral.

Useful settings:

- `EnableDailySummaryEmail`: defaults to `true`.
- `DailySummaryLastSentFilePath`: marker file used to send the synthesis only once per day.
- `-ForceSendDailySummary`: resends the daily synthesis for validation or controlled retests.

## Weekly History

The inventory script can keep one weekly snapshot of the consolidated AD inventory CSV files.

- `EnableWeeklyHistory`: defaults to `true`.
- `WeeklyHistoryFolderPath`: defaults to `{{DataAllRootPath}}\ActiveDirectory\Inventory\WeeklyHistory`.
- `WeeklyHistoryRetentionWeeks`: defaults to `52`.
- Weekly history keeps the canonical enriched `AD_Users_AllDomains.csv` and `AD_Computers_AllDomains.csv`; raw `_Brut.csv` files remain available only in the current inventory and `DATA-LAST`.
- A weekly snapshot is marked complete only after every enabled canonical inventory CSV is present. An incomplete week is rebuilt by the next successful run.
- When SharePoint upload is enabled, every weekly snapshot file is published under `DATA-ALL/ActiveDirectory/Inventory/WeeklyHistory/<year-week>`, followed by `manifest.json`. The manifest records the publication status so completed weekly snapshots are not uploaded again on every run; an existing snapshot without this status is published automatically.
- `DeleteTemporaryPerDomainCsv`: defaults to `true`; the current per-domain temporary folder is deleted after consolidation.
- `TemporaryPerDomainRetentionDays`: defaults to `2`; abandoned timestamped folders under `Not-CSV-Combined` older than this value are deleted at the start of a normal inventory run.

## Adaxes attributes

`SmartM365-ActiveDirectory-Adaxes-Inventory.ps1` (PowerShell 7) reads users through the Adaxes service with the Adaxes PowerShell module (`Get-AdmUser`). Adaxes virtual attributes (`adm-CustomAttribute*`) are stored by Adaxes, not in Active Directory, so this is the only collector that can read them; it is a documented exception to the ActiveDirectory module rule of this folder.

Output: `AD_Adaxes_Users.csv` in `{{DataAllRootPath}}\ActiveDirectory\Adaxes` and `DATA-LAST`, with weekly history. Columns: `TenantKey`, `RunId`, `CollectedAtUtc`, `CollectionStatus`, `IsPartialInventory`, `SourceScriptVersion`, `Domain`, `ObjectGUID`, then one column per configured attribute. Join it to `AD_Users_AllDomains.csv` on `ObjectGUID`, which is unique across the forest and survives renames and moves. Dates are written in UTC ISO 8601, multi-valued attributes are joined with ` | `.

Settings in the private `SmartM365-ActiveDirectory-Adaxes-Inventory.local.json`:

- `AdaxesService`: Adaxes service host name, or a list of host names tried in order. Required; the run fails when it is empty. For each domain, a failed read is retried on the next service; the run then ends with warnings, and the domain fails only when every service failed.
- `Attributes`: list of `{ "Column": "<CSV column>", "Attribute": "<attribute name>" }`. The column names are plain identifiers and must not repeat the fixed columns. Keep the real attribute mapping in the private file only; the committed template contains neutral examples.
- `Domains`: domains to read. Empty means every domain of the current forest.
- `LdapFilter`: defaults to enabled and disabled user accounts without `adminCount=1`. Adaxes cannot build a user object whose `objectClass` the running account cannot read, which typically happens on protected administrator accounts, and such an object stops the read of its whole domain.
- `NonBlockingDomainErrors`: domains whose read failure is tolerated. The other domains are still published, rows carry `IsPartialInventory=true` and the run ends with warnings. Any other domain failure fails the run and keeps the previous export.

Requirements: the Adaxes PowerShell module (a component of the Adaxes installer; it is not installed automatically) on the collection server, and read access in Adaxes to the configured attributes for the running account. The orchestrator job `AD-Adaxes-Inventory` is disabled in the template and requires the `Adaxes` capability. Use `-ValidateOnly` to read without publishing and `-SelfTest` for the offline contract.
